# Follow a security adoption model


Adopting Zero Trust security across your organization is a complex, multi-year effort spanning strategy, architecture, deployment, and operations.

Without a structured approach, security modernization can become fragmented, reactive, and difficult to sustain.

The security adoption model provides a standardized, repeatable, role-aware process to help you plan, prioritize, and implement end-to-end security modernization across hybrid, multicloud, and multi-platform environments.

It aligns business outcomes, security disciplines, and solution implementation so that business leaders, security designers, and practitioners can move forward together at a controlled and sustainable pace


> [!TIP]
> Microsoft offers a rich set of security adoption workshops - the *Security Adoption Framework (SAF) workshops*. Our structured adoption model we describe here aligns with the expert-led guidance available in the workshops. Learn more about our [SAF workshops](workshop-business-overview.md).

## Adoption model alignment

The security adoption model aligns with the Microsoft Security Adoption Framework (SAF) workshops available through Microsoft Unified.

## Why use an adoption model?

Our structured adoption model helps you to:

- **Align with security best practices** - Align security modernization with Zero Trust principles, Microsoft best practices, and external Zero Trust frameworks.
- **Maximize existing investments** - Get more value from tools you already have before introducing new capabilities.
- **Deliver an end-to-end security strategy** - Connect business priorities to security architecture, controls, processes, and operations.
- **Adapt continuously** - Evolve security posture and strategy as threats, business needs, and technologies change.
- **Prioritize action** - Provide practical role-specific guidance teams and stakeholders, grounded in best practices, lessons learned, and real-world examples.

## Model structure

The adoption model is built on three core components that help organizations move from business intent to security implementation:

- **Business scenarios** define why security change is needed in terms of typical business outcomes.
- **Security disciplines** Define how teams plan and operate to deliver security modernization.
- **Technology pillars** gather together assets and resources that we want to secure.


:::image type="content" source="media/adoption-navigation-structure.png" alt-text="Diagram showing overall structure of the Microsoft Security Adoption Framework (SAF)." lightbox="media/adoption-navigation-structure.png":::

Each component targets a specific audience and role in the adoption process.

**Section** | **Primary audience** | **Aim**
--- | --- | ---
**Business scenarios** | Business leaders | Define and communicate critical business outcomes that security must support.<br/><br/>Translate business priorities into actionable security goals that guide planning and decision-making.<br/><br/>Provide practical, repeatable guidance for common business outcomes, with clear paths to the roles and disciplines involved in delivery.<br/><br/>[Learn more](security-adoption-business-scenarios-overview.md) about business scenarios.
**Security disciplines** | Security leaders/teams, IT leaders, designers, architects. | Bridge business scenarios and implementation.<br/><br/> Ensure that security investments and priorities translate into measurable outcomes through clear planning, architecture, and operational practices.<br/><br/>Business scenarios usually map to multiple security disciplines. Learn more about [security disciplines](security-adoption-discipline-overview.md).
**Technology pillars** | Technical and security implementers and partners. |  Define what needs to be secured and where Zero Trust principles and security controls must be applied, such as identity, devices, and data.<br/><br/>Connect security strategy to implementation by grouping related technologies, controls, and capabilities.<br/><br/>Business scenarios are likely to cross multiple technology pillars. For example, if our business scenario focuses on improving security posture across the enterprise, then we'll need to improve posture across devices, data, infrastructure, networks, and more.<br/><br/>[Learn more](implement-overview.md) about technology pillars.

## Adoption guidance

Our structured adoption guidance focuses on:

- End-to-end guidance for common business-critical security scenarios.
- Product-agnostic recommendations based on Zero Trust principles, Microsoft best practices, [Secure Future Initiative (SFI)](sfi/secure-future-initiative-overview.md) patterns, and [open standards and guidance](security-zero-trust-frameworks.md).
- Detailed implementation guidance using Microsoft security products and services.
